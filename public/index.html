RAG Demo

Each tab exposes one stage of the pipeline, so you can see what retrieval and generation actually do - and where they fail.

  • Search — retrieval only. Dense (cosine), BM25, hybrid RRF, or Voyage reranking over the knowledge base. Shows the ranked chunks, scores, and (for rerank) the dense/BM25 ranks. No LLM.
  • RAG answer — one grounded retrieval-augmented pass: the reranked top 5 chunks → LLM (structured output) → answer with validated [S#] citations and the source list.
  • CAG answer — Cache-Augmented Generation: no retrieval at query time, the entire knowledge base travels in a stable cached prefix. Same model and output contract, citations are [D#].
  • Agentic — like RAG answer, but the model may call search_kb (bounded) when the sources are insufficient; shows the retrieval trace.
  • Compare — the same question through RAG and CAG side by side, with latency, token usage, source counts and answers.
  • Eval — evaluation sets. Retrieval: Hit@k, Recall@k, MRR per retriever, plus recall of the expected chunk. Generation: answerable/unanswerable accuracy, citation validity, expected source hit.

Eval

top-k - the final ranking cutoff. Hit@k counts a query as correct if the expected item is within the top k positions, and MRR only credits ranks up to k. Retrieval in the eval is fetched deeper (candidates=20) so Recall@10/@20 can be measured independently of k.

Retrieval - column names

  • Retriever - Dense · Dense+metadata · BM25 · BM25+metadata · Hybrid (RRF) · Hybrid+metadata · Rerank · Rerank+metadata.
  • Doc H@1 / H@3 / H@5 - share of questions whose expected document is in the top k.
  • Chunk H@1 / H@3 / H@5 - same, for the expected chunk (only queries that declare one).
  • MRR@k - mean reciprocal rank: 1/rank of the first correct result, 0 if not found within k. Higher is better.
  • Doc / Chunk R@10, R@20 (Candidate recall) - share where the expected item is anywhere in the first 10 / 20 results. This is the candidate pool a reranker can reorder; if it is not here, no reranker can help.
  • Document rank / Chunk rank tables - per retriever: #n = rank of the expected item, MISS = not found, – = no expectation for that query. The last column shows the expected document (and chunk).

Generation eval - column names

  • Answerable - answered and cited the expected source.
  • Unanswerable - correctly returned insufficient for questions the KB cannot answer.
  • Citations valid - every cited id exists and every answered response has at least one [Sn].
  • Source hit - the expected source document appears among the cited sources.
  • Table - id · type (ans/unans) · status (answered/insufficient/error) · src (expected source hit) · facts (expected facts present) · citations (S ids used) · question.
